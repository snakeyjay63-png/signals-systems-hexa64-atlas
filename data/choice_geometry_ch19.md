# Chapter 19 · Choice Geometry / Reflective Closure

Chapter 19 does not introduce another representational substrate. It makes the
existing **choice points** explicit.

The basic operator is:

`F_θ : X → Y`, with `θ ∈ Θ`.

`θ` selects one admissible mapping/configuration. Once `X` and `θ` are fixed,
the execution path is deterministic.

## Geometric branch

`SVG vector --R--> PNG raster --B--> Base64 --B^-1--> PNG`

and, only if a vectorizer is deliberately introduced:

`PNG --V--> SVG'`.

Base64 is exact on bytes. Rasterization and later vector reconstruction are not
mutual inverses in general.

## Symbolic branch

`Unicode/UTF-8 → Σ73 → abjad → dr/T-orbits → Frame → transformer slice`.

Each arrow is backed by an explicit committed choice or invariant. The registry
records which is which.

## Reflective closure

The repository serializes the selected operator and its parameters back into
the generated artifact:

`θ → F_θ → F_θ(X) → encode(θ,F_θ,results)`.

This is a provenance/reflection property: the structure records the choices
that generated it. It is **not** the stronger claim that the choices cause or
select themselves.

The resulting project chain is:

`carrier → encoding → geometry → finite field → language → dynamics → quotient frame → transformer slice → choice operator → reflection`.

`theta_bridge : Σ73 ↔ abjad`

`lock_policy = NONE_BY_DESIGN`

The default route prefix is separately recorded as `0.0.0.0/0`.

Any nidra/sunya interpretation of the open endpoint is project-defined
semantics, not a networking or physics invariant.

The accounting remains:

`Θ_used \ Θ_locked = {θ_bridge}`

but the interpretation changes: this is not a pending gap. It is the one
explicitly **open-by-design** port. Consequently:

`closure_complete = false`

and:

`closure_semantics = OPEN_BY_DESIGN`.
